Elite remote UI redesign

Harmony Elite panel: ILI9341, 240×320 px, RGB565, single-touch Synaptics pad over the panel, plus a touch strip below it that the driver reports as KEY_FAVORITES (left, ACTIVITIES) and KEY_HOME (right, DEVICES). Mockups below are drawn at exactly 240×320. The grey bar under each mockup is the physical strip, not pixels. The Current column is rendered from today's remote/app/ui.c via the host memory framebuffer (LVGL 9.2.2, Montserrat 14/20).

Assumed physical size: 2.4″ diagonal → about 167 PPI, 0.152 mm/px (not in docs/hardware/remote-elite.md; check with calipers). So 44 px ≈ 6.7 mm, 52 px ≈ 7.9 mm.

1. What makes the current UI look poor

  • Every action is the same saturated blue slab (#2A6FDB). Activity, app shortcut and Power Off look identical, so nothing reads as more important.
  • No state shown. The running activity is not marked, tiles have no on/off look, and buttons give no pressed feedback (LV_OBJ_FLAG_CLICKABLE is removed, so LVGL never draws a pressed state).
  • No status bar. No battery, no hub link indicator, no page context. The only health signal is a whole-screen "Hub unreachable" in 14 px text.
  • Weak type hierarchy: page titles are 14 px regular, the same as button labels. Tile text at 20 px wraps unpredictably ("Blinds / 40%") and long labels wrap instead of ending in "…".
  • Cramped, uneven spacing: 2 px insets and 0 px screen margin. Widgets touch the panel edge, the gaps between them are 4 px, and the grid follows the 320/rows division, so row heights vary by a pixel.
  • Icon-free: 3×4 grids of words with nothing to recognise at a glance in a dark room.
  • Grey-on-grey tiles (#2B3138 with a #4A5560 border) look disabled next to the blue buttons.
  • Dead-end states: boot, fallback and empty screens are one centred word, with no reason, no progress and no next step.

2. Design system for this panel

Grid & spacing

4 px base unit. Screen margin 8 px. Gap 4 px (A) or 8 px (B). Top bar 32 px (title plus link and battery); content box 240×288 at y=32. A 3-column grid gives 72 px cells; a 2-column grid gives 108–110 px cells. Row pitch 52–56 px.

Touch targets

Floor 44×44 px (6.7 mm). Preferred ≥52 px tall (7.9 mm) for primary controls. Single-touch pad, fuzz 3, so keep ≥4 px dead gaps and hit-test the visual box, not the cell.

Radii & lines

A: radius 6, 1 px hairlines, 3 px accent bars. B: radius 10 (buttons), 14 (cards), pill 20–26. No shadows, no gradients, no opacity below 100% (RGB565 bands them and the CPU pays per pixel).

Icons

One 2 px-stroke line set (shown here as SVG) about 40 glyphs: activities (tv, music, game, film), transport, nav, HA domains (bulb, scene, thermo, blinds, switch, fan), status (rf, rf-off, sync, warn, battery). Ship as an LVGL icon font at 20, 24 and 32 px, 4 bpp. Material Symbols Rounded (Apache-2.0) or the harmony-ng stock icon set both fit.

3–4. Screens: current vs Direction A vs Direction B

A · Instrument

Calm and flat, near-black. Content is typography-led: lists with hairlines, outlined controls, one amber accent used only for "what is on". Cheapest to draw and easy on the eyes in a dark room.

B · Cards (recommended)

Filled cards, bigger icons and a teal accent; lights that are on glow warm. Every target looks like something to press. It reads better at arm's length and the hierarchy is stronger. It costs slightly more fill, which is still well within budget.

Active activity marked (A: amber bar + subtitle; B: filled teal card + ON pill). "Play Games" shown pressed. Power Off is set apart, never the same treatment as an activity.

Screen-off → wake

  1. Sleep: the backlight fades 26→0 in 4 steps over 200 ms (stock does 1 step per 50 ms), then fb0 stays mapped and the last page stays in the framebuffer.
  2. Wake (key, touch or accelerometer): with the backlight still 0, refresh the top bar only: battery read, RF icon set to "sync" (amber) until the first hub reply. Then ramp the backlight 0→26 in 3 steps over ~100 ms. The user never sees a half-drawn frame or a flash of the boot screen.
  3. Once the hub replies, the RF icon goes neutral. If there is no reply within 3 s, it goes red, and after 10 s the hub-unreachable screen replaces the page. A key that woke the remote is still sent (or queued).
  4. No content animation. Page changes are a single full redraw; at most a 2-frame cross-fade of the top bar title.

5. Implementation notes (LVGL 9.2.2, ARM926, no FPU/GPU)

  • Widgets: keep lv_obj plus lv_label (LV_LABEL_LONG_DOT). Icons are a second lv_label with the icon font. Don't use lv_button or the default theme: build ~8 static lv_style_t (btn, btn_pressed, card, card_active, tile_on, row, bar, toast) once at init in a new remote/app/theme.c. Use LV_STATE_PRESSED through lv_obj_add_state from our own hit-test in input.c, then remove it on release.
  • Fonts: npx lv_font_conv --bpp 4 --format lvgl --no-compress for Ubuntu B20, B18, M16, M13, R12, B11. Range 0x20–0x7E, 0xA0–0xFF, ° … · –. Roughly 15–25 KB each, about 110 KB total. Disable Montserrat 14/20 in lv_conf.h. Uncompressed fonts are faster on this CPU.
  • Icons: about 40 glyphs from Material Symbols Rounded (or harmony-ng stock icons) at 20, 24 and 32 px, 4 bpp, about 35 KB total. Use A8 bitmaps only for channel logos later.
  • Draw cost (estimate, verify on device): a full 240×320 RGB565 frame is 150 KB. Flat fills run at memory bandwidth, about 1–2 ms per full screen. 4 bpp glyph blending dominates: a busy page (~30 labels) takes about 10–20 ms. Corner masks at radius ≤14 cost about 0.1 ms each. Aim for full page ≤30 ms and press feedback ≤5 ms (only the ~72×52 widget area is invalidated). Avoid shadow_width, opa<255, gradients and per-frame animations. Keep LV_DRAW_SW_COMPLEX on for radii.
  • Remote-side only (no protocol change): theme, fonts, pressed state, top bar (battery from sysfs, link from rf_link), content box 240×288, built-in state screens, toasts, wake sequence. Also heuristics: a full-width label in row 0 is promoted to the bar title, a label of the form "Power Off" gets danger styling, and a keyword→icon table (Guide, Menu, Netflix…) adds icons.
  • Doc/semantic change, not wire: page-format.md says a cell spans 240/cols × 320/rows. This becomes 240/cols × 288/rows in a content box at y=32. Update hp_page_hit, ra_ui_widget_box and the golden render hashes.
  • Protocol change (page format v2, additive; v1 still decodes): per widget, +1 byte style (role: default, primary, danger, quiet, nav, active; 3 bits; plus flags) and +1 byte icon id (0 = none; the registry is shared with page_codec.py). tile_update gains a 1-byte state (off, on, unavailable, active, stale). An optional header byte link (next page id) handles multi-page device lists. The 251-byte limit holds: 32 widgets × 2 extra bytes = 64 bytes, so the HA encoder must budget labels.
  • Progress for "Receiving config" needs a total page count. If page_push doesn't carry one, add it to the sync start message, or show an indeterminate "Page 7" until the end.

Task list (first three ship a visibly better remote with no protocol change)

  1. Theme + fonts: theme.c with tokens and static styles, Ubuntu fonts via lv_font_conv, 8 px margins and 4 px gaps, ellipsis labels, distinct button and tile looks. Regenerate render goldens.
  2. Pressed feedback + top bar: pressed state on the hit widget with partial invalidation. 32 px bar with title (row-0 label heuristic), RF state and battery. Content box 240×288 with updated hit-test and doc.
  3. State screens + toasts: hub unreachable (last seen, retry), receiving config, empty, low-battery toast; remove the bare "Harmony" and "Hub unreachable" pages.
  4. Icon font (~40 glyphs) and the keyword→icon and "Power Off"→danger heuristics.
  5. Wake sequence: draw before backlight, 3-step ramp, RF "sync" state until the first reply.
  6. Host PNG snapshot tool (from the render test) so every page change has a reviewable before/after image.
  7. Page format v2 decode/encode (style and icon bytes) in C and page_codec.py, plus vectors. v1 is still accepted.
  8. tile_update state byte, and tile on/off/unavailable/stale rendering.
  9. HA side: page builders emit roles and icons (active activity, Power Off danger, entity domain→icon), and budget labels to 251 bytes.
  10. Paged device lists: next page header byte, page dots or "1/3", hard Up/Down to page.
  11. Favorites page bound to the Favorites strip key, with a channel monogram style (logos later as A8 bitmaps).
  12. On-device perf pass: time full redraw and press redraw with lv_tick; trim fonts and radii if over budget.
